Phase 2A.3 — Scientific Validation Review and Anatomy Migration Plan

Scope and verification
- Read-only review of the current knowledge types, runtime validators, registry, Vitest cases, Brain records, Systems data, atlas mappings, and BodyParts3D attribution.
- No application code or data was changed or migrated. No tests/build were run for this planning-only task.
- Findings below describe code/data currently present; they do not constitute scientific verification.

1. Validation policy audit

ScientificClaim required fields:
- id, subjectId, predicate, status, evidenceIds (array, which may be empty), and confidence { level, description }.
- subjectId and optional objectId must reference registered entities; supplied evidenceIds must reference registered evidence.

Optional claim fields:
- objectId, primitive value, species[], experimentalContext[], limitations[].
- There is no requirement that claims have any evidence, source, species, or experimental context.

Scientific status and confidence:
- Runtime validation restricts status to established, simplified, hypothetical, or simulated; it does not verify the truth or provenance represented by that status.
- Confidence levels are high, moderate, limited, and unknown. A nonempty free-text description is required, but no rubric, calibration, or consistency check exists.
- Status expresses the kind of content; confidence expresses confidence in it. Neither is derived from evidence.
- There is no draft/unreviewed state. Consequently unsourced legacy prose cannot safely be assigned a claim status merely to pass validation.

Relationships and evidence:
- KnowledgeRelationship has subject/object IDs, a free-form predicate, directed/undirected flag, status, evidenceIds, confidence, and optional species/context/limitations.
- Endpoint and supplied evidence references are checked. Empty evidenceIds are accepted. Predicates do not distinguish anatomical connectivity from functional association.
- findRelatedEntities treats directed relationships as traversable in both directions. Query filters cover subject, object, predicate, and status.
- Evidence has sourceIds, free-form evidenceType, confidence, and optional species/context/limitations. Empty sourceIds are accepted.
- Species and experimental context have reusable structures on both evidence and claims/relationships. Validation checks only nonempty strings and known fields; it does not verify taxon identifiers, methods, or compatibility between evidence and claim.
- Source title is required; authors/year/DOI/URL/publisher are optional. DOI/URL are checked only for nonempty strings, not validity.

Verified weaknesses / misleading records currently possible:
- A claim or relationship labeled established can have no evidence; evidence can have no sources.
- Any nonempty predicate/evidenceType and almost any nonempty confidence description pass. No scientific review or source-quality verification occurs.
- Duplicate IDs are rejected only within each record map, not across entity/claim/source/evidence namespaces. Semantically duplicate relationships under different IDs are not detected.
- Registered records are stored and returned by reference; callers can mutate fields after validation and invalidate status, references, or metadata without revalidation.
- No typed anatomical-versus-functional relation category; free-form predicates can blur direct pathways, conceptual associations, and system membership.
- There is no source-to-claim assessment, evidence aggregation, source-type/provenance validation, publication/review state, or citation requirement conditional on status.
- Unknown fields are not rejected consistently; free-text species/context can look authoritative without a controlled vocabulary.
- TypeScript and passing tests validate software behavior, not scientific accuracy.

Recommendations before migration:
- Add a separate review/publication state or staging record so unreviewed legacy text does not need a scientific status.
- Require traceable evidence/source links for reviewed scientific claims and relationships; define policy per status, including how educational simplifications and simulations are sourced.
- Introduce controlled relationship categories (at minimum anatomical, functional/system-membership, and other/unspecified), with directionality documented.
- Freeze/clone registered records or expose immutable snapshots; add tests for post-registration mutation.
- Define a confidence rubric and species/context authority conventions. Do not interpret “unknown” as low confidence or as evidence.

Phase 2B — External Data Source Investigation

Scope and verification
- Investigated official Allen Institute/Allen Brain Map, BrainGlobe, and EBRAINS/Jülich-Brain documentation, and inspected NeuroLab's current Brain viewer, atlas mapping, build script, and existing BodyParts3D attribution.
- No application code or scientific data was changed, migrated, or installed. This is a source review and read-only proof of concept, not a production integration.
- License notes below summarize the cited terms; they are not legal advice. Check terms for the exact dataset/version and NeuroLab's distribution model before use.

Resource comparison

1. Allen Brain Atlas / Allen Brain Map
- Data/API: REST/RMA endpoints and AllenSDK expose structure ontologies, reference spaces, structure trees, expression data, and downloadable annotation/template volumes. The adult mouse atlas is the clearest 3D anatomical starting point. The Allen Human Brain Atlas is a distinct resource and should not be confused with the adult mouse CCF; the latter is not a human atlas.
- Coverage/3D: adult mouse CCF structure tree and 3D integer-labeled annotation volumes at multiple resolutions. Allen also provides other species/stages/resources, but coverage and representation vary by dataset. The Human Brain Atlas includes adult human expression data, not an equivalent human whole-brain CCF parcellation.
- Use/licensing: Allen Terms of Use permit use, copying, display, and derivatives for research or other noncommercial purposes, require attribution, and restrict commercial redistribution absent written permission. The citation policy specifically requires clear, discoverable dataset attribution/link on the same page as displayed data. A free educational app is not automatically determined to be noncommercial by this review; obtain legal/product approval.
- Reliability/limits: useful, structured reference ontology and experimental datasets, but atlas labels/reference spaces are model-specific. A reference label does not establish a functional claim, and mouse anatomy should not be presented as human anatomy.

2. Allen Mouse Brain Connectivity Atlas
- Data/API: AllenSDK and Brain Map APIs provide metadata and experimental AAV projection data, including structure-level projection summaries and 3D projection-density, injection, and data-mask volumes.
- Coverage/3D: mouse experiments registered to the adult mouse CCF; volumes are available at several voxel resolutions.
- Use/licensing: Allen terms and citation requirements apply; cite the specific experiment/dataset and source atlas where used.
- Reliability/limits: valuable evidence for tracer observations in particular experiments, not a complete synaptic connectome or a universal statement that every region pair is connected. Respect injection coverage, experimental design, and the valid-data mask; do not convert schematic Systems edges into measured pathways.

3. BrainGlobe Atlas API and Atlas Assets
- Data/API: BrainGlobe Atlas API is a Python library that gives a common download/access interface across independently produced atlases; it is not itself a single hosted atlas or a browser JavaScript API. Atlas objects expose reference/template, annotation, structure metadata, and mesh access (including mesh generation from structures).
- Coverage/3D: the official current catalog includes multiple mouse ages/modalities, adult mouse Allen CCF at 10/25/50/100 µm, adult human MRI atlas at 500 µm, rat, zebrafish, and developmental atlases. Availability and versions change; choose the specific atlas, age, modality, resolution, and ontology deliberately. Annotation volumes and structure meshes support 3D workflows.
- Use/licensing: the BrainGlobe software repository is BSD-3-Clause; that licenses the software, not every dataset it downloads. The Atlas Assets specification requires provenance/licensing/references in asset descriptions and supports citations/manifests; inspect the actual atlas asset's license and attribution before bundling or redistributing it.
- Reliability/limits: useful as an ingestion/normalization layer, not as evidence that different atlases are anatomically interchangeable. Coordinate spaces, ages, modalities, labels, and annotation completeness differ. The Allen adult mouse reference is STPT-based; not every modality or region is equally suited to it.

4. EBRAINS siibra / Jülich-Brain
- Data/API: siibra-api is an HTTP API for querying atlas parcellations, regions, templates, and linked regional datasets; siibra-python provides programmatic access. Jülich-Brain provides human probabilistic cytoarchitectonic maps and linked multimodal data.
- Coverage/3D: human atlas resources span MNI, fsaverage surface, and BigBrain histological reference spaces; BigBrain is a 20 µm 3D human model. EBRAINS' viewer describes human, macaque, rat, and mouse atlas options. Both volumetric and surface visualization are supported.
- Use/licensing: EBRAINS describes its infrastructure/tools as open/free, but that is not a blanket license for every linked dataset. Verify licensing, citation, access, and redistribution terms for each map/feature.
- Reliability/limits: probabilistic maps represent inter-individual variability, not a single exact boundary for every person. Reference-space transforms and dataset/map versions must be retained. Some linked datasets may be metadata-only or have separate access/terms.

Recommended source strategy
- There is no one atlas appropriate for every NeuroLab species and use. For a first machine-readable 3D anatomy pilot, use the adult mouse Allen CCF/Reference Atlas as the primary reference space, accessed through BrainGlobe for ingestion and its standard atlas interface. This recommendation is conditional on confirming the noncommercial/license fit and must be explicitly labeled mouse.
- Do not replace NeuroLab's existing human BodyParts3D view with mouse geometry. Keep BodyParts3D v4.0 as the current human presentation asset under its existing CC BY 4.0 attribution. For human probabilistic cytoarchitecture, evaluate Jülich-Brain/EBRAINS as a supplement after per-map rights and coordinate-space fit are reviewed. BrainGlobe's adult human listing may also be evaluated, but is a separate atlas, not an automatic crosswalk.
- Use Allen Connectivity only as an experimental evidence source for specific mouse tracer observations. Consider EBRAINS/Jülich-Brain for human multimodal/probabilistic context. Do not mix them into generic "connection" edges without preserving experimental evidence and source context.

Fit to NeuroLab and proposed integration
- Current verified path: BrainVisualization loads /models/brain/bodyparts3d-atlas.glb; brainVisualizationData.ts maps legacy region IDs to GLB object names, colors, mesh IDs, and coverage notes; click handling looks up the corresponding legacy BrainRegion. scripts/build-brain-atlas.mjs builds the bundled GLB from BodyParts3D OBJ segments. The existing model has partial grouped lobe coverage and no dedicated prefrontal mesh.
- Keep scientific identity separate from atlas/presentation records. Add source/atlas metadata (provider, dataset and release, species/strain/age/sex when specified, reference space, ontology version, modality, resolution, terms, citation, and asset checksum) outside the core entity's scientific claims. Keep large volumes and meshes as versioned external/static assets, not registry records.
- Store provider structure IDs as external identifiers and maintain a reviewed crosswalk to NeuroLab's stable IDs. Do not replace existing Brain IDs or equate matching names across species/ontologies. The current core types support entities, sources, evidence, and claims but do not yet define structured atlas releases, coordinate spaces, or external-identifier crosswalks; those are an explicit integration gap, not implemented here.
- Import hierarchy as typed anatomical part-of relationships with source/version provenance. Keep experimental projection evidence separate from anatomical containment, functional association, and the schematic Systems/Activity edges.
- For visualization, preprocess selected annotation masks into versioned mesh assets and map their atlas labels to reviewed internal IDs. Preserve the existing BodyParts3D asset and viewer path during a pilot; external API access should not be required for ordinary page rendering. Pin versions and retain attribution locally with every packaged asset.

Risks, limitations, and approvals

- API availability, terms, datasets, and atlas releases can change. Pin source versions and checksums; avoid relying on live third-party requests for critical rendering. A data source's scientific reputation does not itself verify every claim NeuroLab might make from it.

Phase 3A — First Biological Neuron Model

Implemented
- Added an independent, typed Hodgkin-Huxley engine in `src/simulation/neuron/hodgkinHuxley.ts`; no UI dependencies.
- Integrates a single isopotential squid-axon compartment with classical voltage-dependent m, h, n gates. Uses outward-positive ionic currents: `INa=gNa*m^3*h*(V-ENa)`, `IK=gK*n^4*(V-EK)`, `IL=gL*(V-EL)`, and `Cm*dV/dt=Iapp-INa-IK-IL`.
- Units: voltage mV, time ms, capacitance μF/cm², conductance mS/cm², current density μA/cm². Defaults: V0 −65 mV, Cm 1 μF/cm², gNa 120, gK 36, gL 0.3 mS/cm², ENa +50, EK −77, EL −54.3 mV, and temperature 6.3 °C. Gates initialize at steady state for V0.
- Uses fixed-step fourth-order Runge-Kutta (default 0.01 ms; maximum step is reduced as temperature increases), splits integration at pulse edges, and scales gate rates with Q10=3. Input/state checks throw explicit errors; simulation-step count is capped.
- Added the computed model as a fourth choice in the existing Lab Learning models. Controls adjust pulse amplitude/duration, Na/K maximum conductance, and temperature; charts show computed voltage, ionic/applied currents, and m/h/n gates. Activity's synthetic traces and the three conceptual Lab models remain unchanged.

Scientific basis and limits
- Hodgkin AL, Huxley AF (1952), “A quantitative description of membrane current and its application to conduction and excitation in nerve,” Journal of Physiology 117(4):500–544, DOI https://doi.org/10.1113/jphysiol.1952.sp004764 (Europe PMC bibliographic record: PMID 12991237).
- Checked NEURON's canonical squid mechanism at https://github.com/neuronsimulator/nrn/blob/master/src/nrnoc/hh.mod for the absolute-voltage convention, squid conductances, rate equations, vtrap singularity handling, and Q10. Checked its explicit example at https://github.com/neuronsimulator/nrn/blob/master/share/examples/nrniv/nmodl/hh1.mod for a parameterized comparison.
- Reversal-potential variants differ slightly between implementations: this app uses +50/−77/−54.3 mV (Na/K/leak); the NEURON `hh1.mod` example uses EK=−77.5 mV. Do not interpret outputs as an exact replica of every HH implementation. The selected −77 mV set leaves a small resting drift (under 0.1 mV over the tested 20 ms); resting gates are initialized at steady state, but voltage is not artificially clamped.
- This is a classical single-compartment squid-axon model, not a complete human neuron. It does not model morphology, spatial propagation, synapses, or many cellular mechanisms; it is neither a physiological recording nor a clinical predictor.

Phase 3B — Biological Synaptic Transmission

Implemented
- Added an independent deterministic synapse engine at `src/simulation/synapse/chemicalSynapse.ts`. A supplied presynaptic terminal-voltage waveform drives a first-order, voltage-dependent CaV activation fraction and an expected single-channel calcium current. Inward current feeds a point-source local-calcium estimate; intracellular calcium relaxes toward that estimate through a first-order clearance approximation.
- Calcium-dependent fusion uses a Hill relationship and an expected fusion rate scaled by a finite one-site vesicle pool. Output samples include time, imposed terminal voltage, channel activation, signed calcium current, local calcium, release probability, expected released vesicles, and available vesicles. Integration uses RK4 with waveform-knot-aware steps.
- Added `src/simulation/synapse/hodgkinHuxleyTerminalInput.ts` as an explicit adapter from the existing single-compartment Hodgkin–Huxley voltage trace. This is an imposed terminal input; it does not model spatial propagation along an axon.
- Added the synapse model as a fifth option in the existing Lab model picker. Users can run the HH-derived terminal waveform and adjust HH stimulus, channel conductance/activation threshold, sensor distance, calcium clearance, Hill coefficient, and effective calcium half-activation. Charts display computed model values; no prerecorded trace is used. Existing Brain, Activity, protocol preview, conceptual Lab models, and HH model remain in place.

Scientific basis and limits
- Scarnati MS et al. (2020), “Presynaptic Calcium Channel Open Probability and Changes in Calcium Influx Throughout the Action Potential Determined Using AP-Waveforms,” *Frontiers in Synaptic Neuroscience* 12:17, DOI https://doi.org/10.3389/fnsyn.2020.00017. The source studies P8–P12 mouse calyx of Held and supports the cited CaV activation onset and example values (43 mV calcium reversal, 2.76 pS single-channel conductance, 220 μm²/s diffusion) and point-source local-calcium method. These are preparation-specific, not universal constants.
- Matveev V, Bertram R, Sherman A (2011), DOI https://doi.org/10.1016/j.brainres.2011.05.011, supports preparation-dependent calcium cooperativity; it does not establish one universal release Hill coefficient.
- The linear activation curve and its saturation voltage, activation/clearance time constants, default sensor distance, effective release half-activation, fusion-rate limit, and one-site pool are explicit modeling assumptions, not fitted constants. Calcium uses a local point-source estimate plus first-order clearance, not a spatial diffusion/buffering simulation. Fusion is deterministic and expected; there is no discrete stochastic channel/release, pool replenishment, molecular SNARE model, transmitter diffusion, receptor, or postsynaptic response.
- This model does not claim complete biological synaptic transmission. The linked HH single compartment does not propagate an action potential spatially.

Phase 3C — Three-Neuron Network

Implemented
- Added a reusable synchronous network engine with three independent single-compartment Hodgkin–Huxley neurons (A, B, C), two directed chemical synapses (A→B and B→C), and an external pulse applied to A. Each connection owns its own presynaptic calcium/release state, glutamate-cleft concentration, and postsynaptic AMPA activation state.
- Reused the existing Hodgkin–Huxley and Phase 3B synapse equations through exported state, derivative, current, and sampling helpers; no second implementation of those biological kernels was added.
- Each RK4 stage evaluates all neuron and connection derivatives from the same network state. The default 0.005 ms step is reduced as needed for Hodgkin–Huxley temperature limits and the configured chemical time scales; integration steps also end at external-pulse boundaries.
- Added the network to the existing Lab model picker. Its controls adjust A's pulse amplitude/duration and AMPA maximum conductance. Computed traces show membrane voltages, calcium current/concentration, expected release, cleft glutamate, AMPA activation/current, firing events, and directed connection identity. The glutamate indicator exposes its 0.0001 μM display threshold rather than treating below-threshold baseline release as zero.

Model equations, evidence, and assumptions
- Cleft glutamate: d[Glu]/dt = expected vesicle release rate × glutamate molecules per vesicle ÷ (Avogadro constant × cleft volume) − [Glu]/clearance time constant.
- Effective AMPA activation: ds/dt = kon[Glu](1−s) − koff·s; conductance density g = gmax·s; outward-positive current density I = g(Vpost−Erev). The sign is inverted when passed to the HH model, whose applied current is inward-positive.
- Default illustrative parameters: 3,000 glutamate molecules/vesicle, 2×10⁻¹⁷ L well-mixed cleft, 0.5 ms first-order clearance, kon=0.01 μM⁻¹ms⁻¹, koff=0.5 ms⁻¹, gmax=0.5 mS/cm², and Erev=0 mV. These defaults are not fitted to one preparation or universal measured constants.
- The HH component is the classical squid-axon single-compartment model. Presynaptic voltage is supplied directly as a terminal input; there is no axonal propagation, conduction delay, or spatial geometry. The transmitter/AMPA stages are effective deterministic approximations, not complete diffusion, receptor-binding, or postsynaptic-morphology models.
- References used for component equations/mechanisms: Hodgkin & Huxley (1952), DOI https://doi.org/10.1113/jphysiol.1952.sp004764; Scarnati et al. (2020), DOI https://doi.org/10.3389/fnsyn.2020.00017; Clements et al. (1992), DOI https://doi.org/10.1126/science.1359647; Destexhe et al. (1994), DOI https://doi.org/10.1162/neco.1994.6.1.14. These motivate components but do not validate the combined network or its default parameterization.
